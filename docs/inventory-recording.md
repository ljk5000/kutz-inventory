# Recording at reload, logout and exit

KutzInventory collects game data while playing. It checkpoints queued work before leaving the world, while player APIs still have useful values; `PLAYER_LOGOUT` seals the cached record instead of rescanning unloaded data. The game writes **both** saved tables (`KutzInventoryDB`, `KutzInventoryObsDB`) into the account's `SavedVariables/KutzInventory.lua`. Only `/reload`, logout or normal exit writes those in-memory changes to disk; a crash/forced termination can lose them.

## Collection and freshness

| Data | Collection/shutdown behavior |
| --- | --- |
| Location | Movement stops, zone/loading events and safe checkpoints. Unavailable readings preserve the last good coordinates on the same map; a different map never inherits them. In dungeons/raids, only instance name/type is stored as character location. |
| Carried bags | Batched bag-update events read dirty bags. An unloaded backpack cannot clear the cached inventory. |
| Gear | Equipment/inventory/durability events queue coalesced scans; safe checkpoints flush pending work. An empty gear read preserves an existing record. |
| Gold/XP/rested XP | Delayed login reads, immediate money/XP/exhaustion events and manual scan. Reads stop while leaving; checkpoint handling avoids a new teardown zero overwriting gold. |
| Professions, currencies, skills, spells, talents, reputation, PvP | Login/change events queue scans. A checkpoint can finish queued work while player data are usable; unavailable client APIs may leave fields absent or old. |
| Stats/sheet | Latest safe out-of-combat reading; changes during combat can defer updates. Buffs at snapshot time count. |
| Statistics/achievement points | Login, manual scan and post-combat reads throttled to once per ten minutes. From 1.21.0 each read also notes the values that changed since the read before under today (`chars[key].statDays[day][id]`), kept 30 days; the first read notes nothing. |
| Character/warband bank | Requires the bank open and loaded. Cached values represent a visit, not a live view after closing it. |
| Guild bank | Only viewable tabs visited/loaded by the server can be recorded. |
| Recipes/trainers | Requires the corresponding UI/data. Recipe reads skip linked/guild/NPC professions; unlearned entries depend on what the window lists. From 1.21.0 an unlearned recipe is saved once per account file (`KutzInventoryDB.recipeBook[recipeID]`) and a character's book keeps IDs (`unlearnedIds`; a record that differs from the shared one is kept whole in the list). The first login moves every character's lists, also those of characters not logged in. The hunter's Beast Training window is not stored as a trainer (1.16.0; it used to replace the class trainer's list). |
| NPC summary (`KutzInventoryObsDB.npcs`) | Target, mouseover, an open vendor/quest/trainer window and loot corpses, at most once per NPC per 30 s and only while drop tracking is on; cells only while within about 10 yards (or a window is open with it). Inside an instance (1.21.0) there are no cells: the instance map and difficulty are counted instead, at most once per NPC and instance per 10 minutes. |
| Item facts (`KutzInventoryObsDB.items`, 1.21.0) | Every item met in bags, banks, worn gear, loot and roll lists, vendor stock and quest rewards waits in a queue while drop tracking is on. One read per 0.25 s from a link of the item ID (and suffix) alone; none in combat or under 20 frames a second; a 10 s pause after a read over 8 ms and a stop for the session after three in a row. Read again when the game build changes. Capped at 200 kB of the saved file; the least recently met go first and are read again when met again. The queue is in memory only: an item still waiting at logout is read when it is met again (bags and worn gear at the next login). |
| Kills per day (`KutzInventoryObsDB.kills`, 1.21.0) | `UNIT_HEALTH` for a dead creature no other player tapped, while the player is fighting or stopped within 2 s; once per corpse in a session. One number per day, NPC ID and level; 30 days, at most 800 numbers. |
| Vendor prices | Ready rows at merchant events plus a delayed retry for late rows. From 1.21.0 the vendors that are not the cheapest stay listed under the item (`also`, at most 8), each with its NPC ID, price, limited flag and time seen. |
| AH prices | Only explicit AH commands start scans. Completed responses survive; pending responses cannot finish after the UI closes. |
| Craft counts | In-memory updates on your own system creation messages, persisted on the next game save. |

Checkpoints are requested by hooks for `Logout`, `Quit`, `ReloadUI`, by `PLAYER_LEAVING_WORLD`, and shortly after `PLAYER_ENTERING_WORLD`. They flush queued work only when the player GUID, loaded backpack, world state and login delay indicate usable data. Old timer callbacks are invalidated. Final logout sets save diagnostics, cancels queued work and copies an optional `KutzUIDB.monitor.findings` report.

`characters[].recording` exports save/checkpoint times, checkpoint reason, pending/failed scan names and whether stats were deferred. Per-category `updated` stamps help inspect age. No pending work does **not** mean every bank/trainer was visited or every asynchronous request finished. Inventory 3.x intentionally omits ordinary character stats/talents/reputation/PvP and matching update stamps; format 2 retains them.

The Companion polls saved-file timestamps/sizes every second; it starts with an immediate export/upload and coalesces later file changes/retries. The CLI watches its initially selected files with the same queue; both read a sibling `KutzUI.lua` monitor save when present and prefer newer findings. A monitor-only change does not trigger export. Neither tool can force the game to save or guarantee freshness after a crash. [Upload and privacy behavior](../README.md#privacy-and-uploads) applies to all save paths.

## Activity modules

`Crafts.lua` matches localized `LOOT_ITEM_CREATED_SELF`/`LOOT_ITEM_CREATED_SELF_MULTIPLE` system loot messages, with English fallbacks. A stack of five increments item count by five and craft-message count by one. Conjured items count too; other players' creations and ordinary received loot do not. This always-on feature writes `chars[key].crafted`: first observed craft time, running total, per-item count/message count/name/last time, and the newest **120 dates on which crafting happened** (local dates). It cannot reconstruct earlier activity. Format 3 exports the optional `crafted` block with up to 5,000 most recently crafted item types; format 2 omits it.

`Observations.lua` is default-on for a new install/missing preference; existing off choices persist. It records loot sources/roll lists, quests, vendor stock, trainers' lists (class and profession trainers; never the hunter's Beast Training window) and, from 1.18.0, flight masters' reachable nodes with their prices and how long each flight took (node ids only, no position trail). From 1.18.0 a quest accept also carries the quest log's level, group size, daily/weekly and time-limit facts and the starting item, and a turn-in the reward window's XP and the per-faction reputation changes (two reads a second apart; never a standing, dropped when loot, combat or another quest came in between); quest money is never read. Quest prose comes from detail/progress/completion windows, replacing the character's given name, surname and full name with `$N`, once per quest/action per session and across reloads while retained, under both event half caps. Events also include the character's name/surname and map coordinates outside instances. From 1.17.0 it also keeps a per-install NPC summary (not events) of the creatures the player targets, mouses over, talks to or loots: their names and, from 1.18.0, the services they offer (from the interaction windows opened with them), but no GUIDs, player names, times of day or order of sightings. `/kinv track drops off` stops new recording (both) **without removing old uploadable events or the summary**; there is no local delete command. See [schemas](../schema/README.md#observations-3203130) for limits and fields.

In 1.19.0 drop tracking also records gossip and quest greetings for identified creatures and objects. The recorder replaces the recording character's names with `$N`, drops amounts in gold, silver or copper and drops text with a roster or player target name after scrubbing. Object gossip and greetings also use the same capitalized-word check as NPC say and yell. Gossip options, player chat and mail are excluded.

Readable pages come only from world objects whose GUID and title still match at page read. The recorder checks for an open mailbox and overlapping bag use, requires exactly a nil creator, and checks the material before reading a body. An empty creator string is refused. Bag items and title-only recording are disabled in 1.19.0.

NPC speech and emotes come from an identified, uncontrolled creature. Curly quotes, en and em dashes, and ellipses become ASCII. The recorder scrubs its own and recipient names, plus known roster and player target names when capitals appear past sentence starts. Whispers and emotes allow only `I` and its common contractions as unresolved capitals. Say and yell also allow words from the speaker's name, zone, subzone and the common English word list. An unknown lowercase player name or a name matching an allowed word can still appear in a line or gossip. Consumers should publish a text only when two different recorders sent the same text for the same subject.

Quest accepts can include objective types, required amounts and wording, with the recording character's given name, surname and full name replaced with `$N`. Progress counters and completion status are excluded. Quest markers come from `C_QuestLog.GetQuestsOnMap` on the acceptance map while out of combat. Missing data can fill the same accept event shortly after it is saved.

From 1.20.0 a hunter's tames are recorded: the beast's creature ID from the target's GUID when Tame Beast began (nothing without one; never guessed from the pet), its level and family, and what the new pet showed within a minute: spellbook abilities with ranks (each spell ID checked against the book's name, kept once two reads in a row agree), the main-hand attack speed read out of combat (flagged when the pet had an aura at every read), the diet and the client's locale (the labels' language). The new pet must bear the target's name, and its level and creature ID wherever both are readable; a cast the client says went to another unit (a mouseover or focus macro), a pet more than 2 seconds after the channel ended, or anything else in doubt records nothing. Passive reads only; the pet's GUID and name and the target's name are compared in memory and never kept. A tame event is about 395 bytes; at most 20 a session.

From 1.20.0 objective credit is recorded: about a second after the quest log changes, each monster, item and object objective's `numFulfilled` is compared with the last read in memory (it is never saved or exported). When one rose and the player's own evidence of the 6 seconds before names exactly one cause (a creature a unit token showed dead that no other player had tapped, an item from the player's own "You receive loot / item" line, an object whose window the player opened), the event keeps the quest, the objective's index and type, how many objectives the quest listed (`rows`, to line `i` up with the accept's `obj`), that one id and how it was told: `name` (named in the objective's text) or `sole` (a creature only, the only one, never while grouped or with a pet out). Items and objects are told by name only; a loot window from an object (a chest, a herb or mining node) is no evidence. The first read of a session and quests new to the log set the comparison only. A credit event is about 295 bytes; once per quest, objective and id per install, at most 200 a session (about 60 KB at worst).

New text events stop at 2,500 saved events or when the added event would exceed the first 1,000,000 bytes of the approximate saved-event cap. A bounded saved index suppresses duplicate events across sessions. Rejected NPC lines use a session-only checksum cache. A cached rejection skips unit, roster and location reads on repeat. Existing installs see a one-time login notice that describes the new recording and the `/kinv track drops off` command.

The synthetic examples add 469 Lua bytes per gossip, 584 per read page, 443 per line and 419 per quest accept with two objectives and two points. Their compact export sizes are 299, 390, 273 and 201 bytes respectively. The addon's cap estimates for those examples are 302, 394, 276 and 207 bytes. As a size illustration, a long city session with 50 unique recordable lines, 20 gossip texts, five pages and five such quest accepts adds about 39 KB to SavedVariables, including dedup keys and excluding the preexisting fields of the five accepts. Repeats add no data while their keys are kept. At capacity, the five FIFO indexes (gossip, read, line, tame and credit, 2,000 keys each) take up to about 480 KB of Lua using the example serializer: about 285 KB for the three text indexes and 200 KB for tame and credit, with every id at its longest (a tame key is the creature ID, level and a 16-character checksum, whatever the pet's book holds). The live file size varies with text lengths, serializer overhead and other activity; the size half cap is measured against the approximate saved-event size.

`Raids.lua` records only manually tracked raid strings within their active window while grouped/instanced. It includes group rosters and system loot messages, with other players' names. `Prices.lua` records vendor prices and manual AH scans independently of the observation switch. No module sends HTTP requests; desktop upload is separate.

## Hearth, Legacy Trees and identity

`GetBindLocation` supplies the hearth name after loading screens and `HEARTHSTONE_BOUND`; an empty answer preserves the last good one. It exports as optional `characters[].hearth` in 3.x.

Legacy Tree ranks/currency are scanned with talents, including queued pre-leave checkpoints. Any staged or incomplete scan preserves the previous complete reading; the applied ranks are used. Both export formats include `legacyTree` when usable.

GUID ownership is selected before any character write. Existing keys stay stable; colliding given names get surname/GUID-based keys. Guild events refresh a delayed name while preserving the old name if membership remains true; explicit false membership clears it.

## Verification

`node tools/check_inventory_logout.js` loads the real addon into an offline Lua VM and exercises reload, logout, Quit and native-exit paths, including unavailable player/map APIs before final events. It checks immediate bag/XP changes, live coordinates, queued checkpoints, late empty/zero data, stale timers, diagnostics, Legacy Trees and guild-loading behavior. `check_crafts.js`, `check_observations.js`, `check_raids.js`, `check_prices.js`, `check_character_identity.js` and `check_scheduling.js` cover their modules. `node tools/check_all.js` runs them with conversion/schema and Companion tests.

Live acceptance still needs WoW Forever: move to a known position, change a bag stack or gain XP, reload/log out/Exit Game normally, and inspect the saved/exported data and timestamps. Visit bank/profession/trainer UIs separately; test combat-deferred reads and same-name logins. A forced process kill is not a normal-save test. Server acknowledgement is a separate upload test, not evidence about all server privacy controls.

### WoW Forever 1.21.0 checklist

Nothing in 1.21.0 was run in the game: it was written against the client's API documentation and checked in the offline harness. Back up `WTF/Account/<account>/SavedVariables/KutzInventory.lua` first and note its size.

- Log in on a character with professions and type `/kinv`. Expect no Lua error and no last error. Type `/run local n=0 for _ in pairs(KutzInventoryDB.recipeBook or {}) do n=n+1 end print("shared recipes", n)`: expect several hundred on a file with professions. Type `/run for _,c in pairs(KutzInventoryDB.chars) do for p,b in pairs(c.recipes or {}) do print(p, b.unlearned and "OLD LIST" or "moved", b.unlearnedIds and #b.unlearnedIds or 0) end end`: every line must say `moved`. Open each profession window with "show unlearned" on and compare the unlearned count with the window's.
- Type `/kinv perf` a few seconds after login. Expect two lines: `item facts: N held (x of 200 kB), M waiting, R read this session. Kills counted today: 0.` and `time used per frame by item facts and kill counts: worst A ms, average B ms, over F frames; S slow reads (over 8 ms).` Stand still out of combat for a minute and type it again: R grows by up to four a second and M falls to 0. Note A, B and S. If the first line says `stopped for this session`, note the reason it gives.
- Pick a plain item in the bags and type `/dump KutzInventoryObsDB.items[<its id>]`. Expect `d` (a day number), `b` (an index into `KutzInventoryObsDB.itemBuilds`, which holds the build text), `f` like `"1:0:7:5:5:0::"`, and `t` whose lines start with `-` (the first is the item's name unless `n` holds it). For a piece of gear also `s` (stats) and a `>` line for the right text ("Shield"). Check an item with a requirement the character does not meet: that line starts with `!`.
- Type `/dump C_TooltipInfo.GetHyperlink("item:6948", nil, nil, true)`: are the lines under `lines[i].leftText`, `rightText`, `leftColor` and `rightColor`, and is there no "Sell Price" line? Type `/dump C_Item.GetItemStats("item:6948")` and the same for a piece of gear: a table of numbers?
- Get a random-suffix item ("... of the Bear" or the like) from loot or a vendor, or have one in the bags. Type `/dump KutzInventoryObsDB.items[<the plain item's id>].v`: expect one key like `"0;12729"` holding the full name, and after a line break stats only if they differ from the plain item's. Check that no other entry in `items` was made for it. Then type `/dump C_Item.GetItemInfo("item:<id>::::::::::::1:<bonus id>")` and `/dump C_Item.GetItemStats("item:<id>::::::::::::1:<bonus id>")`: do the name and the stats include the suffix? If not, variants keep the name from the link and no stats, which is the safe result.
- Loot that item, or open a vendor selling one, then type `/reload` and search the saved file for its name: the link must be `|Hitem:<id>::::::::::::1:<bonus id>|h[...]` (or plain `|Hitem:<id>|h` for an item with no suffix).
- Kill three creatures and loot none of them. Type `/kinv perf`: `Kills counted today: 3`. Type `/dump KutzInventoryObsDB.kills`: one day with `"<npc id>:<level>"` keys. Then stand beside another player's fight without helping (their tapped mob dies): the count must not rise. In a group, a mob the group tapped and a groupmate finished must count once.
- Enter a dungeon, target a creature, leave, and type `/dump KutzInventoryObsDB.npcs[<its id>]`: expect `inst = { ["<instance map>:<difficulty>"] = 1 }`, a name and level, and no `cells`.
- Open two vendors that sell the same item. Type `/dump KutzInventoryDB.prices.vendor[<item id>]`: the cheaper one on top with `npc`, `t`, and the other under `also`.
- Play for ten minutes with a fight in it, type `/kinv scan`, then `/run for _,c in pairs(KutzInventoryDB.chars) do for d,v in pairs(c.statDays or {}) do local n=0 for _ in pairs(v) do n=n+1 end print(d, n) end end`: today's day number with the count of statistics that changed since the read before (a character's very first read notes nothing).
- Type `/reload`. Compare the saved file's size with the backup's: smaller by about what the unlearned recipes freed, plus what was recorded since. `/dump KutzInventoryObsDB.perf` after the reload shows the numbers of the session before. Export with the Companion or `node tools/inventory_export.js` and run `node tools/validate_export.js` on the result.
- In a city with a full bag and bank open, watch for stutter while `M waiting` is above 0. Report the worst and average from `/kinv perf` after a normal play session of an hour.

### WoW Forever 1.20.0 reputation read checklist

- With the reputation window open, confirm the addon does not rescan (opening and closing headers) every 5 seconds.
- Collapse the Inactive header and nested headers (a header inside a collapsed one), with the window open and closed, and confirm each is put back as it was after a read.
